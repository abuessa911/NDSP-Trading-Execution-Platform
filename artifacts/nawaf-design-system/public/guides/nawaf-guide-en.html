Overview and review tools

What this package is, what it is not, and how to browse it.

@workspace/nawaf-design-system is a standalone, token-driven library of interface components for the NAWAF financial control console. The Dark theme follows the console source; the Light theme is derived for review. It contains 18 component families, 139 public components and 7 utilities and providers (counts are computed live from the catalog).

This is a review package, not a migration plan. Do not replace console or application code with it without explicit approval. Replacement candidates in the reference notes are documentation only. It is also not a trading, user or administration manual.

Browsing and review tools

  • Navigation: the sidebar groups Guides, Foundations and the six component groups. On narrow screens a menu button opens it; Escape closes it.
  • Search: the sidebar field filters pages by name and description in both languages.
  • Deep links: pages use #page=<id> (for example #page=buttons). Guide chapters add &chapter=<id> (for example #page=guide&chapter=family-tables).
  • Language and theme: the two header buttons switch English or Arabic (which also flips page direction) and Dark (source) or Light (derived). Both choices persist in local storage under the nawaf-ds-review.* keys.
  • Inventory: the Inventory page lists every family with component, utility, variant, size and state counts plus their display labels.
  • Every demo is a sample: nothing is live, saved or connected, and each family page links back to its guide chapter.

Install, exports and CSS setup

Wiring a consumer is a separate decision that needs explicit approval. Nothing in this guide authorizes migrating the console or any app.

CSS setup (verified against the generator)

styles.css is generated by scripts/build-tokens.mjs. It already imports Tailwind, tw-animate-css, the typography plugin, generated/tokens-extra.css and component-theme.css, and registers this package component sources with @source. A consumer therefore needs only one import and no extra Tailwind import or node_modules source path.

React and Vite recipe (illustrative)

  1. Add the dependency as workspace:* and install.
  2. Import styles.css once, from the app main CSS.
  3. Render one primitive such as Button, then run the consumer typecheck and dev server before anything else.
  4. Set lang and dir on the root element and wrap the app in DirectionProvider (next chapter).

Only web is supported. There are no native components; Expo or other platforms may import the generated tokens object only. Components never import with an @/ alias, so they resolve through the package paths.

Direction, language and theme

How reading direction, language and theme are set and kept consistent.

Direction needs three things to agree: the dir and lang attributes on the root element, the DirectionProvider that tells Radix about keyboard direction and portals, and logical CSS classes (ps, pe, start, end, text-start) instead of physical left and right.

Theme: source dark, derived light

Dark values are copied from the console source. Light values are derived for review and are not part of the source. Switching theme toggles the dark class on the root and sets color-scheme; components read only CSS variables, so they need no per-theme code.

Who owns the copy

Component default props stay English and their API is unchanged. Callers supply localized copy: demos in this review app pass tr(english, arabic) results, and a real consumer passes its own translations. Components never read the language themselves.

Isolating mixed content

  • Technical snippets, class names, import paths and token identifiers: a code element with dir="ltr" and lang="en", never part of the prose.
  • Signed financial numbers and currency codes: wrap in bdi dir="ltr" so the sign and digits never reorder.
  • Natural embedded names inside a sentence: use bdi so the surrounding punctuation stays correct.
  • Chart geometry stays left to right while captions and table headers follow the page direction.

Switching language at runtime

Keep controlled state (selected tab, chosen option, typed text) keyed by language-neutral values so it survives a switch. Sample text a user has not edited should follow the language; text the user typed must be preserved. The review app does this with a useSample helper: edited text wins, otherwise the sample follows the language.

Composition patterns

Controlled and uncontrolled state, validation, help text and focus restore.

Controlled and uncontrolled

Use the value/onValueChange (or checked/onCheckedChange, open/onOpenChange) pair when other UI depends on the state. Use defaultValue when only the user cares. Never switch one component between the two modes.

Validation and help text

  1. Give the field a Label with htmlFor.
  2. Put help text in an element with an id and reference it with aria-describedby.
  3. On error set aria-invalid="true", add the border-destructive class, and show a message with role="alert".
  4. Say how to fix it, not only that it failed.

Dialog focus restore

Radix returns focus to the element that opened the dialog when it closes, but only if that element is still mounted. Use DialogTrigger asChild around a real Button; when opening a dialog from code, keep a ref to the opener and focus it in onOpenChange when open becomes false. DetailDrawer restores focus to the previously focused element itself.

Motion and focus

  • Focus: all controls show a focus-visible ring; never remove it.
  • Motion: durations and easings come from motion tokens, and generated CSS removes animations and transitions under prefers-reduced-motion.
  • Animate only transform and opacity.

DataGrid in depth

The generic API, translation function, All sentinel, ids, sorting, search and details.

  • Row ids: T must have a unique string id. It is the React key and the details test id. Keep ids stable across language switches.
  • The t function translates column labels, filter labels, filter option values and the All sentinel. Treat the English strings as keys; return the translation or the key itself.
  • The All sentinel: each filter select starts at the string All and shows t("All"). A filter matches a row when the value is All or equals pick(row). Always include an All entry in your translation map.
  • Search: a case-insensitive substring match over the joined value() of every column. To make search work in the active language, return localized text from value for text columns.
  • Sort: clicking a header cycles ascending, descending, then none, and sets aria-sort. Numbers sort numerically; strings use localeCompare.
  • Stale labels: memoize cols and t on the language so column labels refresh; filter state keeps its English option values, so a language switch never leaves a stale selection.
  • Details: each row has a button named labels.details plus detailTitle(row). The drawer lists every column not marked hideDetail through KV, then detailExtra.
  • Empty: when no row matches, EmptyState renders your empty copy.

Numbers and chart accessibility

Isolating numerals and giving every chart a text alternative.

  • Formatters money, signed and num always format as en-US and output Latin digits. Render them inside bdi dir="ltr" (or via Kpi and Pnl, which already do).
  • Say "account value" rather than a stock term when the number is a balance.
  • Every chart needs an accessible name that states shape and range, and a table of values as an alternative. PreviewChart includes the table; add one for LineChart and Bars.
  • Do not encode meaning by color alone: rising and falling lines also differ in the caption text; positive and negative bars are listed with signs in the table.

01. Buttons

Action button with six variants and four sizes.

The single action control. Use it for every click target that performs an action.

Public exports (1 components, 1 utilities), read from the catalog:

  • Button
  • buttonVariants

When to use it, and when not to

  • Use it: A command (save, confirm, retry) or an icon-only action. Use variant="link" with asChild for navigation that should look like a link.
  • Avoid it: Do not use a button to navigate between pages without asChild, and do not use destructive for routine actions.

Composition

Button accepts any native button attribute. buttonVariants({ variant, size }) returns the class string for non-button elements.

Testing and review checklist

What to verify before accepting a change.

  • Typecheck and build pass (pnpm typecheck, pnpm build).
  • Both languages: no untranslated explanatory text; identifiers appear only inside isolated code.
  • Both directions: layout mirrors, arrow keys mirror, signed numbers stay left to right.
  • Both themes: contrast holds and no color is the only signal.
  • Keyboard only: every control is reachable, focus is visible, overlays trap and restore focus.
  • Narrow screen: no horizontal page scroll; tables stack or scroll inside their wrapper.
  • Reduced motion: no animation remains.
  • Every new component has a family demo, a catalog entry and a registry entry.

Limitations

What the package deliberately does not do.

  • Web only. There are no native components; other platforms use the tokens export.
  • No data fetching, authentication, routing or business rules. Demos use sample data.
  • Number formatters are fixed to en-US and the dollar sign.
  • Component defaults are English: callers must supply localized copy.
  • The Light theme is derived and is not source.
  • Migration of any app to this package requires explicit approval.
