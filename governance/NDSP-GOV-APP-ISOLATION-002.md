# NDSP-GOV-APP-ISOLATION-002 — الحوكمة الملزمة لعزل التطبيقات والتغييرات
**الإصدار:** 1.0.0  
**التاريخ:** 2026-11-19  
**المالك:** مالك منظومة NDSP  
**النطاق:** كل تطبيق أو خدمة أو واجهة أو محرك أو عقد أو نطاق فرعي أو مستودع أو بيئة أو بوت يتبع المنظومة حاليًا أو مستقبلًا، بما فيها المنصة الرئيسية والإدارة والمستخدم وAPI وRadar وBot وAudit وDesign وAlsarra ومختبرات الأبحاث، وكذلك مشاريع التنفيذ المستقلة عند تعديلها.  
**الأولوية:** سياسة عابرة للمستودعات؛ تُطبّق مع `NDSP-GOV-QA-001` دون تخفيف أي شرط قائم. لا تغيّر هذه الوثيقة مواصفات NEX المجمدة أو استقلال مختبر NMP أو الصلاحيات السابقة.

## 1. القاعدة الثابتة غير القابلة للتجاوز بصمت
> **أي تعديل أو إضافة أو إصلاح يخص تطبيقًا محددًا لا يملك حق تعديل تطبيق آخر أو عقده أو محركه أو تصميمه أو بياناته أو نشره أو صلاحياته، مباشرةً أو عبر اعتماد مشترك، دون موافقة صريحة موثقة من المالك، وتحديد الأثر، واختبارات مستقلة على كل جهة متأثرة.**

يشمل المنع التغييرات غير المباشرة في API المشتركة، قواعد البيانات، migrations، المصادقة والتفويض، بيانات الأسعار، الطبقات، المحركات، NMP/TDL، قائمة الخدمات، Nginx وPM2 وsystemd وDNS وTLS وCI/CD، أسماء المسارات، حزم الاعتماديات، CSS/themes العامة، الهوية المعتمدة **Modern Plus Gold**، التعريب، الاشتراكات والتجربة، والأسرار. الصمت أو نجاح بناء واحد **ليس موافقة**.

## 2. نوع التغيير ومكان تنفيذه
1. **تغيير الحوكمة فقط:** يُوثَّق مباشرة داخل مستودعات المصدر الرسمية، مع رقم إصدار وتاريخ وبصمة، ويُزامَن مباشرةً إلى دليل الحوكمة على خوادم الإنتاج **كملفات سياسة غير تنفيذية فقط**. يُمنع أن تتسبب مزامنة السياسة وحدها في إعادة تشغيل خدمة، أو تعديل كود التشغيل/التهيئة، أو المساس ببيانات العملاء أو الأذونات. عند تعذر وصول الإنتاج يُعلن `PRODUCTION_MIRROR_PENDING`، ولا يُختلق نجاح.
2. **أي تغيير غير حوكمي:** يبدأ في **بيئة معزولة قابلة للاختبار** لا تمس النظام الحي أو المصدر المرجعي المعتمد. عند نجاح الاختبارات والموافقة، يُنقل إلى فرع مراجعة مستقل في مستودع المصدر المعتمد، ثم PR مع أدلة G0–G7، وبعد اعتماده فقط يجوز النشر للإنتاج المستهدف. لا ترقيع runtime ولا اعتماد تجارب شكلية على أنها اختبار حقيقي.
3. **تغيير مشترك أو عابر للتطبيقات:** يُصنَّف `CROSS_APP` حتى إن ورد في ملف واحد. لا يبدأ دمجه أو نشره قبل تحديد جميع المستهلكين، موافقة مالك المنظومة الصريحة في سجل تغيير، واختبارات regression/contract/security/impact عليهم. لا يستبدل التصنيف `N/A` بالدليل.
4. **استثناء طارئ:** لا صلاحية لتجاوز فصل الصلاحيات أو تعديل تطبيق آخر خفية. يتطلب `change_id` وسببًا وموافقًا وفترة انتهاء وخطة رجوع وسجل تدقيق؛ يظل المصدر المرجعي والتوثيق اللاحق إلزاميين. لا يُنشئ هذا النص تصريح نشر أو تداول آلي.

## 3. سجل النطاق/التأثير الإلزامي لكل طلب تغيير
يُرفق مع كل طلب تعديل غير حوكمي:
- `change_id`، المستودع والفرع وcommit SHA، التطبيق/الدومين **المستهدف الوحيد**، مالك الخدمة، وصف التغيير ونوعه (`ISOLATED_APP` أو `CROSS_APP` أو `GOVERNANCE_ONLY`).
- المسارات والملفات المسموح تعديلها، والمسارات **المحظور** تعديلها، وعقود Consumer/Provider وإصدارات API وقواعد البيانات والخدمات المشتركة.
- قائمة التطبيقات المتأثرة مباشرة أو ضمنيًا، وخطة التجارب المعزولة، ونتائج الاختبارات والإثبات أن البقية لم تتغير وظيفيًا أو بصريًا أو أمنيًا.
- القرار البشري الصريح لأي أثر عابر، وروابط PR، وأدلة QA، وخطة النسخ الاحتياطي/الرجوع، ونطاق النشر، ووقت UTC.
- إذا تعذر جرد المستهلكين أو تحديد الأثر تُسجَّل `BLOCKED_UNMAPPED_DEPENDENCY` ويُمنع الدمج والنشر.

## 4. معايير الحظر والفصل
- لا يُسمح لتغيير Radar بإعادة بناء أو نشر أو تعديل Portal/Admin/API/Bot أو العقود المشتركة إلا بتصنيف `CROSS_APP` موثق وموافق عليه. وينطبق العكس على جميع التطبيقات.
- أي ملف مشترك أو route عام أو قاعدة بيانات أو خلفية أو إعداد بنية تحتية يُعامل كمنطقة تأثير عابرة حتى يثبت خلافه باختبارات وعقود؛ **عدم وجود تعديل ظاهر في واجهة أخرى لا يثبت عدم التأثير**.
- تُثبت ملكية كل تطبيق وعقوده وموارد إنتاجه. لا مشاركة لرموز نشر/أسرار/صلاحيات بين خدمات مستقلة إلا بعقد أمني معتمد. لا مفاتيح تداول حية أثناء تجارب البوت.
- المنطق الأصلي لـTDL وNMP والدايفرجنس واستقلال محامي الشيطان، البحث الخاص، سياسة `fail-closed`، الصلاحيات، الباقات، هوية Modern Plus Gold، ومحتوى الدليل والترجمة لا تتغير ضمن عمل غير متعلق بها.
- لا خلط بين `mock` و`live`، ولا بين `NOT_RUN` و`PASS`، ولا بين غياب الإشارة وتعطل مصدر البيانات.
- النشر دائمًا إلى **الخدمة المحددة فقط**، لا تنفيذ شامل أو Restart للخادم؛ النسخ الاحتياطي والخروج الآمن واختبار الاستعادة ومراقبة الأثر قبل ختم الإصدار.

## 5. بوابة تحقق قابلة للتدقيق
**G0** جرد المستودع والتطبيق وكل المستهلكين؛ **G1** اختبار عزل يفشل عند محاولة تأثير خارج النطاق؛ **G2** فحص العقود والإصدارات والتوافق الخلفي؛ **G3** API وAuth وRBAC وبيانات حقيقية في QA؛ **G4** واجهات عربية/إنجليزية وموبايل/تابلت/كمبيوتر وثبات هوية Modern Plus Gold عند الاقتضاء؛ **G5** مراجعة الفروقات للتأكد أن الملفات خارج القائمة لم تتغير؛ **G6** CI وإثبات SHA وreview بشري وموافقة الاستثناء؛ **G7** نشر موجّه ومراقبة ورجوع اختباري.

أُضيف إلى فحوص PR شرط مستقل باسم `application-boundary` يحظر التغيير المتقاطع دون بيان نطاق وموافقة، ويجب جعل الاختبار **Required** على الفروع المحمية ومنع bypass وفرض مراجعة مالك الكود، عبر إعدادات GitHub المصرح بها. إذا غاب الاختبار أو حماية الفرع: `ENFORCEMENT_INCOMPLETE` لا `PASS`. لا يجوز لوكيل مراجعة PR الخاص به.

## 6. قواعد توزيع حوكمة الإنتاج
- المرجع المصدر: `governance/NDSP-GOV-APP-ISOLATION-002.md` بكل مستودع مع تعليمات `AGENTS.md`.
- النسخة التشغيلية للحوكمة فقط: `/etc/ndsp-governance/NDSP-GOV-APP-ISOLATION-002.md`، بدون أي تغييرات أخرى في ملفات التشغيل.
- تُحفظ النسخة السابقة عند تحديث الوثيقة، وتُقارن SHA-256 لمحتوى السياسة بالمصدر الرسمي. اختلاف المصدر والإنتاج يساوي `GOVERNANCE_DRIFT` ويتطلب المعالجة قبل أي إصدار جديد.
- جميع المستودعات والتطبيقات الجديدة مطالبة بضم السياسة قبل أول طلب دمج/إصدار؛ لا إعفاء بسبب عدم وجود واجهة أو API.
- مستودعات الأرشيف تخضع لحماية البيانات والمصدر والسجل، دون تفسير وجود السياسة أنه تصريح بتحرير أدلة سابقة.
- السياسة دائمة إلى أن تُعدَّل بطلب حوكمي صريح بإصدار أعلى وسجل تدقيق؛ لا تعديل أو حذف صامت.

## 7. قرار التنفيذ
**المسموح الآن:** تثبيت/مزامنة **ملفات الحوكمة** فقط في المصدر الرسمي والإنتاج، دون تغيير سلوك التطبيقات.  
**الممنوع الآن:** دمج PR وظيفي، أو نشر تطبيق، أو تغيير عقد/منطق/تصميم/خدمة بناءً على هذه الوثيقة وحدها.

**حالات الإبلاغ المعتمدة:** `SOURCE_POLICY_INSTALLED`, `PRODUCTION_MIRROR_INSTALLED`, `PRODUCTION_MIRROR_PENDING`, `ENFORCEMENT_INCOMPLETE`, `BLOCKED`. لا تُستخدم كلمة «مكتمل» إلا بعد أدلة المصدر + نسخة الإنتاج + إعدادات حماية الفروع/الاختبارات حيث تنطبق.
